# 汇报叙述与配图框架

更新：2026-11-03。本文件先固定文字叙述、图位与证据边界；现场图片、截图和真机录屏由后续素材补齐。没有用示意图冒充实车画面。

## 1. 项目一句话

在非EDU差速轮椅上，通过ESP32 BLE HID与App摇杆执行适配建立可接收ROS连续速度的底层，再结合双MID360、Odin与原生Nav2，形成从目标位姿、几何规划到实车执行的导航系统。

## 2. 推荐叙述顺序

### 第一部分：平台与接口约束

介绍轮椅差速结构、Jetson、两个MID360和Odin的位置。说明当前不是使用开发版底盘SDK，而是从原有App控制入口接入。先让听众理解为什么需要单片机/HID适配，而不是直接展示ROS节点名。

拟用图注：**轮椅硬件与后轴坐标系。**标出前进方向、后轴中心、窄踏板、传感器安装和Jetson/ESP32位置。位置标注应依据真实安装与标定，不按照片透视估计尺寸。

### 第二部分：打通底层通信与执行

沿着USB→ESP32→BLE HID→iPad虚拟摇杆→原厂轮椅控制链讲解。区分USB别名、HID蓝牙连接、App状态和实际运动，说明ESP32的职责是输入设备适配。

拟用图注：**从ROS速度到既有App控制入口。**USB串口与BLE HID使用不同箭头，并将App至轮椅的原厂链路单独画出。

### 第三部分：从粗方向步长到连续速度目标

先展示旧方向指令如何移动鼠标，再解释保持按下拖动、精细相对位移帧与连续速度逆映射。强调八方向参考点不是最终控制挡位，底层报告依然量化。

拟用图注：**相同虚拟摇杆上的粗步长与精细位移。**若使用对照录屏，应尽量固定App档位、指针设置、速度意图与场景，不用不同工况的画面对比宣称提升幅度。

### 第四部分：标定与实际反馈

区分界面坐标标定和后轴速度标定。说明前后增益不同、左右转向对称模型、可达速度半椭圆；同时展示期望速度、模型预测与Odin真实反馈。

拟用图注：**虚拟摇杆输入到后轴速度的标定。**稳态拟合与加减速过程分开，注明数据日期、样本工况和误差单位。

### 第五部分：感知与车体几何

介绍双雷达点云如何转成导航scan、地面/自过滤、八顶点轮廓以及两个前角mask。区分原始点云、过滤后的障碍、车体实体框、停止区和膨胀代价。

拟用图注：**窄踏板轮廓、前角遮罩与导航障碍输入。**图片标明使用的topic和frame，不能拿原始3D点云与另一个时刻的costmap直接作因果对照。

### 第六部分：原生Nav2导航链

用一张图介绍目标→BT→Lattice→RotationShim/MPPI→速度平滑→碰撞监控→底盘。讲清原地转向、前进/倒退和车身扫掠的关系。这里说明的是当前单套turn_memory，不展示已删除profile为在线功能。

拟用图注：**规划、局部控制和底盘执行分层。**路径平滑与速度平滑分别标注，不把SmootherServer已启动写成当前BT必经。

### 第七部分：真机演示与结果

按已有素材展示目标到达、转向、近墙减速及障碍触发停车。每段说明当前配置、ARM状态、目标、障碍位置和实际结果。存在失败或跟踪误差的段落保留对应说明，不把挑选的视频当全工况成功率。

拟用图注：**同一时间窗口的目标、路径、最终命令与车辆运动。**优先同步展示RViz和真机视角；若不同步则分别标注。

### 第八部分：工程交接与后续眼控

展示工作区、启动入口、配置/标定清单、源码固定版本与恢复方法。最后说明未来眼控作为独立上层输入接入，具体控制算法与验证完成后再独立上传。当前汇报不展示未完成的眼控实现为正式交付。

## 4. 可以说明和仍需证据的事项

可以据当前代码清楚说明：USB/BLE/App链路、精细帧、连续标定模型、Nav2模块组成、参数和轮廓、源码与原生导航/RDS的边界。历史构建/隔离验证可按原记录注明范围。

仍需最终现场素材或新数据支撑：当前所有蓝牙重连工况、细分HID实际最小速度、不同载荷/地面下的跟踪误差、窄通道所有方向的扫掠、终点过冲分布，以及后续眼控端到端效果。

建议表述为“完成接口集成、标定和指定场景验证”，并说明使用条件；不要写成“直接接管电机”“零延迟”“绝对连续”“通用安全保证”或“全工况稳定”。
